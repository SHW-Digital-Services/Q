Architecture & Infrastructure

Platform Operations for Q Administrators

Secrets & Environment Variables

Rule number one of our Node.js and Express environment: Critical service keys must remain strictly server-side.

  • Never use VITE_: SUPABASE_SERVICE_ROLE_KEY and OPENAI_API_KEY must NEVER be prefixed with VITE_. This prevents bundling them into client-side code.
  • Safe for Client: Only VITE_SUPABASE_URL and VITE_SUPABASE_ANON_KEY are safe to expose to the browser.

Local Setup

Always duplicate .env.example to .env locally. Never commit .env to GitHub.

Enforcing Row Level Security

The Final Defense

We do not rely solely on the frontend or Express backend to filter data. Every table in Supabase containing user memories or journals must have an RLS policy applied.

Example Policy:

(auth.uid() = user_id)

This ensures users can only read or write their own data at the database level, preventing cross-contamination.

PayPal Webhook Verification

  • Mandatory Verification: Our Express server listens for PayPal webhooks, but they must be cryptographically verified using the webhook ID and headers before updating user access.
  • Secure Context Only: Payment secrets must be restricted to trusted server environments.
  • Idempotency: Duplicate event identifiers are recorded and rejected to prevent processing the same notification twice.

Admin Communications Protocols

When acting in an administrative capacity (e.g., account freezes, security notices), all external communications must be centralized.

  • Use the group email: office@q-ai.online
  • Ensure the official Q Admin signature is configured in your email client for all outgoing messages.

Deployments

Ensure all TypeScript validation and CodeQL analysis passes before merging to production.
