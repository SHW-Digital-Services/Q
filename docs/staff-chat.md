# Staff and Admin team chat

The Team chat page is available at `/crm/chat` from the portal sidebar for signed-in accounts whose current profile role is `staff` or `partner_admin`. Choose **Everyone** for the shared conversation, or choose a team member for a private conversation. Offline team members can receive messages and read them on their next visit. Customers cannot access the chat API or the underlying tables. Private messages are accessible through Q only to their sender and recipient, including when another team member is an Admin. Database operators retain database access; this is not end-to-end encryption.

Apply `supabase/migrations/20261008210238_staff_chat.sql` followed by `supabase/migrations/20261008211129_staff_chat_private_messages.sql` to the Q Supabase database before deploying the application changes. The migrations create message history and per-tab presence tables with RLS enabled, grant access only to the server service role, and add private recipients. No Realtime publication or extra client credentials are required.

Messages and presence refresh every eight seconds while the page is connected. Accounts appear once across multiple tabs. Presence expires after 90 seconds without a heartbeat, including after closing a browser or losing a connection. Online indicates a connected session, not active attention. Only the most recent 100 messages load initially; a connected chat keeps up to 500 in memory. Messages stay saved in the database.

Incoming messages show a toast and unread count on other pages, for other conversations, or while the chat page is hidden. Click **Enable sound** inside chat to unlock browser audio; the sound preference is saved per account and restored across pages after browser audio is unlocked. A browser may suspend background pages and delay alerts until the page resumes. Drafts are saved per account in session storage, and failed sends keep their text. Each send uses a request ID so retrying does not duplicate a saved message.

Run `npm run check:staff-chat`, `npm run typecheck`, and `npm run build`. For live verification, sign in with a Staff account and an Admin account in separate browser sessions: open Team chat from the sidebar, confirm both appear, exchange messages, navigate one account to another portal page to verify its toast and click it to return to the right conversation, enable sound and verify the alert, then sign out and check presence expiry. Confirm a customer gets 403 from each chat endpoint. Local checks do not verify deployment or audible playback.

Click **Enable system notifications** on the Team chat page to request browser permission for device notification-centre alerts. Opt-in is saved per account on that browser. System alerts hide message text, link to the right conversation, and suppress duplicate delivery across tabs. You can turn them off without disabling in-app toasts. HTTPS and a compatible desktop browser are required; operating-system notification settings and Do Not Disturb can suppress display. Q must remain open: these are page-delivered system alerts, not background Web Push after the application is closed. On mobile browsers where the Notification constructor is unavailable, in-app toasts remain available. Run `npm run check:staff-chat-notifications` for permission and delivery logic checks; native OS display must be verified on the actual device.
